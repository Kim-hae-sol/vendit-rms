# VENDIT RMS — 새 업로드 패키지

이 패키지는 가격 설정, 경쟁 숙소 비교, 판매 관리 캘린더를 포함한 정적 웹 앱입니다. 비어 있는 저장 객실 목록은 기본 객실로 복구해 캘린더 그리드가 사라지지 않게 했습니다. 브라우저 저장소를 사용할 수 없는 경우에도 기본 화면을 표시합니다.

## 기존 GitHub 파일을 새 버전으로 교체하기

1. ZIP을 내려받아 압축을 풉니다. 파일들이 한 폴더 안에 들어 있습니다.
2. 저장소에 남은 기존 앱 파일을 제거하고, 압축을 푼 폴더의 **내용물 전체**를 저장소 최상위에 올립니다. `index.html`, `app.js`, `styles.css`가 저장소 최상위에 나란히 있어야 합니다. ZIP이나 바깥 폴더 자체를 저장소에 올리면 안 됩니다.
3. GitHub Pages 설정에서 배포 브랜치와 폴더가 저장소 최상위(`/`)를 가리키는지 확인합니다.
4. `index.html`은 릴리스별 버전 쿼리로 CSS와 JavaScript를 불러옵니다. 새 배포가 끝난 뒤 브라우저에서 강력 새로고침을 합니다. 기존 로컬 저장 상태가 남아 화면이 다르면 주소 끝에 `?reset=1`을 붙여 초기 상태로 열 수 있습니다.

## 로컬 실행과 검증

Node.js 18 이상에서 다음 명령을 실행하세요.

```sh
npm run dev
```

브라우저에서 `http://localhost:4173`을 엽니다. 저장 상태 복구, 저장소 비활성, 캘린더 초기 렌더링, 가격 단계 계산 검증은 다음 명령으로 실행합니다.

```sh
npm test
```

## 파일 구성

- `index.html`: GitHub Pages 진입 파일. CSS와 JavaScript 파일을 같은 위치에서 불러옵니다.
- `app.js`: 가격 설정, 경쟁 숙소, 판매 관리 캘린더 동작
- `price-stages.js`: 가격 단계 계산
- `styles.css`: 전체 반응형 화면 스타일과 캘린더 그리드
- `server.mjs`, `package.json`: 로컬 미리보기 서버와 실행 스크립트
- `tests/`: 가격 단계 계산, 저장 상태 복구, 저장소 비활성, 신규 캘린더 렌더링 검사

GitHub Pages는 정적 파일을 제공하므로 `server.mjs`는 로컬 미리보기에만 사용합니다.
